# ADR-0006 — ADC 1.0.4 state machine and TIGR session hash

- Status: Accepted
- Date: 2026-08-19
- Author: gpt-5.6-sol

## Context

v0.0.01 recognized a small set of ADC command prefixes but did not keep the ADC connection state, did not negotiate a session hash, did not verify the client PID/CID relationship and could forward an initial `PD` field.

ADC 1.0.4 defines ordered connection states, requires the connecting client to initiate the session with `SUP`, requires at least one negotiated hash for session identity, and requires hubs to verify `hash(PID) == CID` and discard `PD` before broadcasting INF.

The project needs a concrete, testable profile before adding registered users, permissions or additional extensions.

## Decision

For dc24h.eu-v0.0.02:

1. Implement PROTOCOL, IDENTIFY and NORMAL as per-connection state.
2. Require the ADC `BASE` feature.
3. Support and require `TIGR` as the v0.0.02 session hash.
4. Reply to initial `HSUP` with `ISUP ADTIGR ADBASE`, selecting TIGR before the other advertised feature.
5. Use libgcrypt `GCRY_MD_TIGER1` for canonical Tiger/192 digest output.
6. Decode PID/CID using strict unpadded ADC Base32.
7. Verify the initial `PD` against `ID` before accepting the client.
8. Never place `PD` in forwarded or stored public INF state.
9. Validate that routed client messages claim the connection's assigned SID.
10. Route ADC B, D, E and F message types according to their header semantics.
11. Retain H-type messages inside the hub.
12. Add tests for the state transition, hash vector, privacy and routing checks.

VERIFY is not entered in this release. It is reserved for a later registered-user `GPA`/`PAS` implementation.

## Consequences

The hub rejects clients that do not advertise both BASE and TIGR. This intentionally narrows interoperability in exchange for a deterministic and verifiable identity profile.

PID privacy and sender identity are materially stronger than in v0.0.01. Direct, echo and feature routing can now be extended without redesigning the transport layer.

The build gains a `libgcrypt20-dev` dependency on Debian 13.

The implementation still needs a future normalization decision to enforce the ADC requirement that Unicode text be in NFC, and a future authentication ADR for VERIFY/GPA/PAS.

## Alternatives considered

### Continue without a session hash

Rejected because ADC requires hash negotiation for session identity and because PID/CID verification would remain impossible.

### Implement Tiger directly in the project

Rejected for v0.0.02 because maintaining a local cryptographic hash implementation would add substantial review and test burden without project-specific value.

### Use a different ADC hash extension

Deferred. TIGR is documented by the ADC extension specification and is widely associated with ADC/DC identity and file hashing. Adding another session hash can be done later through a new compatibility decision.

### Implement registered-user VERIFY at the same time

Rejected for this release to keep password challenge/response, account policy and operator permissions in a separate security-focused change.
